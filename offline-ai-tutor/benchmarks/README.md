# 评测说明

本目录含 6 道自行编写的功能测试题，覆盖基础数学、物理和缺失条件情况。
参考答案为人工计算的简单核对项，题量不足以支持普遍教学能力结论。
当前没有把旧报告中的性能数字填写为本仓库的实测结果。

## 生成记录

配置实际本地模型，退出界面演示模式后执行：

```bash
python3 -m scripts.benchmark --condition '设备型号；UI开启；热运行；线程配置' \
  --repeat 3 --output data/reports/model-a-warm.jsonl
```

脚本直接调用实际 Ollama，记录模型标签、摘要、题目哈希、采样配置、输出和模型阶段耗时。
它不测试拍照或 OCR，也不自动评判答案正确性。每个输出文件独占创建，避免覆盖已有测试。
输出包含题目解答，默认不提交 Git；对外发布前选取允许公开的测试内容。

## 需要分别测量的指标

| 指标 | 计时起止 | 必须记录的条件 |
|---|---|---|
| 拍照耗时 | 发起采集到取得有效图像 | 摄像头、预热帧、分辨率 |
| OCR 耗时 | 输入图像到识别文字 | 图像尺寸、模型、线程、是否首次加载 |
| 模型首字延迟 | 发起模型请求到首段可见文字 | 模型摘要、冷/热、思考模式、输入长度 |
| 模型生成速度 | 输出 token 数 / 生成阶段时长 | 输出长度、采样、线程和设备状态 |
| 端到端首字 | 点击拍照到首段可见解答 | 包括采集、OCR、人为校对等待是否计入 |
| 完整流程耗时 | 点击拍照到回答完成 | 同上并记录实际输出长度 |

同条件至少重复若干轮，保留逐次数据，报告中位数、范围和样本量。
UI 开关或 CPU/NPU 对比应控制同模型版本、提示词、输出长度和量化格式；
无法控制时只能称“部署方案对比”，不能把差异完全归因于硬件。

## 人工评阅

逐题记录 OCR 正确性、答案正确性、步骤正确性、结构完整性、是否编造缺失条件及失败原因。
格式符合不代表答案正确；生成更快也不代表教学效果更好。
量化前后及微调前后分别比较，保存错误案例。
